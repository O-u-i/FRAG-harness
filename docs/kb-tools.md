# Selected KB tools

`GET /api/harness/capabilities` lists two executable read-only tools: `kb.search` (native lexical search over selected redacted evidence) and `kb.read` (a real isolated Python CLI process). Neither searches unrestricted files or performs finance operations. Search is a case-insensitive keyword baseline; ranking and citation identity are not factual support.

Create an exact Harness/RAG preview first. Before Context execution, call `POST /api/runtime/runs/{runId}/tools/execute` with `{sourceRequest, call: {callId, name, arguments}}`. Supply the same explicitly selected source request. Tool arguments include the selected `identity`, `revision` and `locatorIds`; read adds `evidenceIds`, search adds `query` and `limit` (default 3, maximum 10). Obtain these IDs from the preview, not from a guessed path. Registration does not authorize access.

The host validates the input schema, selected binding, frozen request, source bytes/index revision, task conditions and Run state before execution. A changed request is rejected before reading another file or plugin. FC and mixed FC selections are rejected by these KB tools. A changed file requires a new Run. Tool calls use unique IDs, are serial and limited to six per Run. Pending/unknown observations prevent model dispatch. Pause/reject is preserved while an already running read finishes.

The CLI carrier has fixed executable/argv/cwd, executable and script content pins, an environment whitelist, structured JSON stdin/stdout, a 128 KiB input limit, a 10-second timeout and a 16 KiB combined stdout/stderr limit. No caller shell string or environment override is accepted. The worker reads only host-supplied selected redacted snapshots; it never opens KB/FC files or contacts a network. Private carrier stdin includes trusted selected evidence alongside validated arguments. `toolInputSchema` describes public tool arguments, while `inputSchema` describes the full carrier envelope; output schemas must match the tool's typed result.

Each authorized attempt is durably claimed before execution. Results must match the owning call ID and selected evidence bytes/metadata. Read must return all requested IDs. Failure records contain sanitized codes, not raw process text. A completed observation, its carrier/version, duration and result appear in the canonical RunReport and Runs page. Schema version 1 remains compatible with older reports through an empty toolCalls default. History does not restore executable tokens. A process interrupted before its outcome was committed becomes outcome_unknown and is not automatically rerun.

Tool reads do not change the already prepared model request, grant an outbound approval or automatically send a model request. Model-driven selection and result feedback belong to the upcoming Research phase. Current tools are independently invocable for acceptance and inspection. [Host CLI](host-cli.md) provides the same tool endpoint; [offline evaluation](offline-evaluation.md) adds synthetic fixture checks without real model calls.
