# FRAG Evidence Tools 1.14.0

Registers `frag_search`, `frag_read`, `frag_fc_read` for the **main VS Code window's native Local Agent**, plus Settings/Runs/Memory Webview. It owns a loopback evidence backend, not a model bridge or Agent loop.

Install matching `frag-host-1.14.0.zip` and `frag-bridge-1.14.0.vsix`. Set `frag.hostInstallation` only for a custom location; keep native model credentials/configuration in VS Code. Open one trusted local folder, authorize sources in **FRAG: Open Settings**, explicitly Build / Refresh, then enable tools in native chat.

The management header offers Dracula dark, Living light or system theme,
Compact/Comfortable density, motion, visible Run count and developer JSON.
Search opens from a magnifier; FC item filters and collapsible sections reduce
clutter without changing selections or authorization. Presentation preferences
persist locally and never change evidence limits or financial rules.

No composer filling, Send interception, AHP registration or final-answer capture. Source data is not authority. Native tool policy is not replaced by FRAG directory approvals. Runs record finalized FRAG results only; legacy records are read-only, never replayed. Installed `resources/install.md` contains upgrade/troubleshooting instructions.

Private state defaults to VS Code extension storage at `projects/<project-hash>/`.
**FRAG: Open Private State Folder** opens that exact directory. Set
`frag.privateStateRoot` in machine-local User Settings for a custom absolute
private local root, separate from source and Host. Stop the backend and reload
after changing; no existing state is moved or deleted. An empty root starts new
approvals/history. Keep state and `fc.env` out of Git/shared/cloud-synced folders;
FC Vaults and native model credentials stay in their respective applications.

**FRAG: Open Acceptance Workspace** opens the Slice A/B guide in Settings.
Its default workspace is `<project-private-state>/acceptance/`; explicit
**Prepare virtual files** creates `README.md` and
`sources/synthetic-plan.md`, preserving existing edits. A custom machine-local
`frag.acceptanceRoot` uses
`<acceptance-container>/projects/<project-hash>/acceptance/`. The panel shows
exact paths and offers folder/plan open actions. Changing location never moves
or deletes files. Authorizing only the test `sources` folder, saving and
building its index, reviewing the whole plan and confirming its revision all
remain separate human actions. Before confirmation or after an unreconfirmed
change, complete-plan reads must refuse.

**Folders & storage** separates user sources, private state, synthetic
acceptance and installed Host. Developer UI/bridge source, `.tmp/` runs and
versioned delivery packages are not customization or private-data storage.
The repository's `docs/management-ui.md` contains the full management and A/B
walkthrough; packaged `resources/install.md` contains setup/troubleshooting.

Recommendation safety is model-free and synthetic only. Runs may show separate allowlisted workflow receipts, never draft bodies or human decisions. Production recommendations are unavailable; the foundation does not filter native chat or establish a provider budget guarantee.
Slice A requires isolated safety checks; Slice B additionally requires whole
confirmed-plan and sufficient official FC economic evidence, with positive and
missing-fact refusal cases. Preparing files is not a pass, account/monthly-flow
reads alone do not prove financial completeness, and this UI enables no Slice C
or production recommendation path.
